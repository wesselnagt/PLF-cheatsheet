PLF08: Windows Server Routing & NAT

Volledige stappen voor het transformeren van Windows Server naar een functionele NAT-router.

Stap 1: Netwerkkaarten Identificeren en Configureren

Open PowerShell op de router-VM om de exacte namen van je netwerkkaarten te achterhalen:

powershellGet-NetAdapter

Configureer de interfaces statisch volgens de criteria van de opdracht:

powershell# Interface richting Core-netwerk (VMnet2)
New-NetIPAddress -InterfaceAlias "Ethernet 1" -IPAddress 172.19.19.1 -PrefixLength 24

# Interface richting interne Active Directory (VMnet0)
New-NetIPAddress -InterfaceAlias "Ethernet 0" -IPAddress 192.168.1.10 -PrefixLength 24
Laat de netwerkkaart die gekoppeld is aan VMnet8 (NAT) altijd op DHCP staan! Dit controleer je met: `Get-NetIPAddress -InterfaceAlias "VMnet8"`

Stap 2: RRAS Rol en NAT Routering Installeren

  1. Open Server Manager, klik op Add Roles and Features.
  2. Klik door tot Server Roles en vink Remote Access aan.
  3. Vink bij Role Services de opties DirectAccess and VPN (RAS) en Routing aan. Voltooi de installatie.
  4. Open de console via: Start -> Administrative Tools -> Routing and Remote Access (of typ rrasmgmt.msc).
  5. Rechtermuisknop op je servernaam -> Configure and Enable Routing and Remote Access.
  6. Kies in de wizard voor Network Address Translation (NAT).
  7. Selecteer de netwerkinterface die met het internet is verbonden (de DHCP/VMnet8 interface) en klik op Voltooien.

Stap 3: Interfaces Handmatig Toevoegen aan NAT (Indien leeg)

Mocht de wizard mislukken of de tabel leeg blijven, voeg de interfaces dan handmatig toe in de console:

  1. Vouw uit: Server -> IPv4 -> NAT.
  2. Rechtermuisknop op NAT -> New Interface....
  3. Selecteer je internetkaart (VMnet8): kies Public interface connected to the Internet + vink Enable NAT on this interface aan.
  4. Rechtermuisknop op NAT -> New Interface....
  5. Selecteer je LAN-interface (VMnet2): kies Private interface connected to private network.

Stap 4: Gateway Strijd Oplossen (Metric Aanpassen)

CRITIEK SYMPTOOM: Kan de router zelf wel op internet via Edge, maar mislukt `ping 8.8.8.8` vanaf Core1? Dan gebruikt Windows de verkeerde hoofdroute. Voer dit uit op de Router:
powershell# Dwing internetkaart naar de hoogste prioriteit
Set-NetIPInterface -InterfaceAlias "VMnet8" -InterfaceMetric 5

# Zet de interne kaarten op een hele lage prioriteit voor internet
Set-NetIPInterface -InterfaceAlias "Ethernet 0" -InterfaceMetric 80
Set-NetIPInterface -InterfaceAlias "Ethernet 1" -InterfaceMetric 80

PLF09: Active Directory Sites & Replication

Het fysiek scheiden van netwerksegmenten binnen AD en het configureren van replicatietijden.

Stap 1: Core Server Promoveren tot Domain Controller

Voer dit uit in PowerShell op de Windows Core-server om Active Directory services te installeren:

powershellInstall-WindowsFeature -Name AD-Domain-Services -IncludeManagementTools

Promoveer de core-server nu tot een extra DC binnen je bestaande domein:

powershellInstall-ADDSDomainController -DomainName "school.test" -Credential (Get-Credential)
Geef bij de pop-up de gegevens van de Administrator van je domein op (bijv. `school\Administrator`). Het systeem zal automatisch herstarten.

Stap 2: Sites en Subnets Aanmaken

Open op de hoofd-DC de console Active Directory Sites and Services (dssite.msc):

  1. Rechtermuisknop op de map Sites -> New Site.
    • Naam 1: Leeuwarden. Selecteer DEFAULTIPSITELINK en klik OK.
    • Naam 2: Groningen. Selecteer DEFAULTIPSITELINK en klik OK.
  2. Rechtermuisknop op de map Subnets -> New Subnet.
    • Prefix: 192.168.1.0/24. Selecteer site Leeuwarden.
    • Prefix: 172.19.19.0/24. Selecteer site Groningen.
  3. Vouw Sites -> Default-First-Site-Name -> Servers open.
    • Sleep je hoofd-DC naar Leeuwarden -> Servers.
    • Sleep je Core-DC naar Groningen -> Servers.

Stap 3: Sitelink Replicatieschema Aanpassen

  1. Navigeer naar Sites -> Inter-Site Transports -> IP.
  2. Rechtermuisknop op DEFAULTIPSITELINK (of maak een nieuwe via New Site Link) -> Properties.
  3. Pas de Replicate every aan naar het gevraagde aantal minuten (bijvoorbeeld: `30` minuten).
  4. Klik op Change Schedule.
    • Selecteer de uren waarop replicatie verboden is en kies Replication Not Available (dit wordt wit).
    • Selecteer de uren waarop replicatie toegestaan is (bijv. Ma-Vr 09:00-18:00) en kies Replication Available (dit wordt blauw).

Forceer synchronisatie en controleer de status via de opdrachtprompt:

cmdrepadmin /syncall /AePdq
repadmin /showrepl

PLF10: Windows Group Policies (GPO)

Het configureren en afdwingen van security-instellingen en gebruikersrestricties via GPO.

Stap 1: Wachtwoord- en Accountbeleid Configureren

BELANGRIJK: Een wachtwoord-policy werkt in een Active Directory domein ALLEEN als deze gekoppeld is aan de ROOT van het domein (of via de Default Domain Policy). Koppel je hem aan een OU, dan negeert Windows de instellingen!
  1. Open Group Policy Management (gpmc.msc).
  2. Rechtermuisknop op Group Policy Objects -> New. Geef de naam GPO_Wachtwoord.
  3. Rechtermuisknop op de nieuwe GPO -> Edit.
  4. Navigeer naar: Computer Configuration -> Policies -> Windows Settings -> Security Settings -> Account Policies -> Password Policy.
  5. Configureer de vereiste waarden:
    • Enforce password history: Bijv. `3` passwords remembered.
    • Maximum password age: Bijv. `20` days.
    • Minimum password length: Bijv. `10` characters.
  6. Sluit de editor. Rechtermuisknop op de root van je domein (bijv. school.test) -> Link an Existing GPO... en kies `GPO_Wachtwoord`.

Stap 2: Command Prompt & Run Blokkering voor Gebruikers

  1. Maak een nieuwe GPO aan genaamd GPO_Restricties.
  2. Rechtermuisknop -> Edit. Navigeer naar: User Configuration -> Policies -> Administrative Templates -> System.
  3. Dubbelklik op Prevent access to the command prompt. Zet deze op Enabled.
    • Optie: Zet "Disable the command prompt script processing also?" op **No** als scripts op de achtergrond nog wel moeten kunnen draaien.
  4. Navigeer naar: User Configuration -> Policies -> Administrative Templates -> Start Menu and Taskbar.
  5. Dubbelklik op Remove Run menu from Start Menu en zet deze op Enabled (dit blokkeert de `Win + R` sneltoets).
  6. Koppel deze GPO aan de specifieke Organizational Unit (OU) waar de doelgebruikers in zitten.

Stap 3: Handhaven (Enforce) & HTML Rapportage

Om te zorgen dat lagere policies deze regels niet kunnen overschrijven:

  1. Klik in Group Policy Management met de rechtermuisknop op de koppeling van de GPO onder je domeinnaam of OU.
  2. Klik op Enforced. Er verschijnt nu een hangslot-icoontje bij de GPO.

Genereer het verplichte inspectierapport via PowerShell:

powershellGet-GPO -Name "GPO_Wachtwoord" | Get-GPOReport -ReportType HTML -Path C:\gpo_rapport.html

PLF11: Windows Systeembeveiliging & PKI

Auditing inrichten en een certificaatautoriteit (Enterprise CA) opzetten in Windows Server.

Stap 1: Auditing (Gebeurtenisbewaking) configureren

Om bij te houden wie inlogt of wijzigingen maakt, configureer je dit binnen een GPO:

  1. Open de GPO editor en navigeer naar: Computer Configuration -> Policies -> Windows Settings -> Security Settings -> Local Policies -> Audit Policy.
  2. Dubbelklik op de gewenste policy, bijvoorbeeld: Audit logon events of Audit account management.
  3. Vink zowel Success (gelukt) als Failure (mislukt) aan.
De logs kun je achteraf op de doelcomputer live inzien via de Event Viewer (eventvwr.msc) -> Windows Logs -> Security.

Stap 2: Active Directory Certificate Services (AD-CS) Opzetten

  1. Open Server Manager -> Add Roles and Features.
  2. Selecteer bij de serverrollen: Active Directory Certificate Services en klik op Next.
  3. Vink bij Role Services aan: Certification Authority. Voltooi de installatie.
  4. Klik bovenin Server Manager op het gele waarschuwingsdriehoekje en kies Configure Active Directory Certificate Services....
  5. Geloofsbrieven: Zorg dat je bent ingelogd als Enterprise Administrator.
  6. Selecteer Certification Authority -> Kies Enterprise CA (zodat het domein de CA automatisch vertrouwt).
  7. Kies Root CA -> Create a new private key.
  8. Laat de cryptografie op SHA256 staan en klik door tot de installatie voltooid is.

PLF12: OpenVPN op Rocky Linux

Volledige commandolijst voor het opzetten van een beveiligde OpenVPN server-client verbinding.

Stap 1: Repositories Schoonmaken & Benodigdheden Installeren

Voer deze commando's uit op **beide** Linux-machines (Server & Client) om installatiefouten te voorkomen:

bash# Repositories herstellen naar de juiste baselines
sudo rm -f /etc/yum.repos.d/Rocky-*
sudo dnf reinstall rocky-repos -y

# EPEL repository installeren (nodig voor OpenVPN)
sudo dnf install epel-release -y

# OpenVPN en Easy-RSA installeren
sudo dnf install openvpn easy-rsa -y

Stap 2: De Certificate Authority (CA) Bouwen (Enkel op OpenVPN Server)

bash# Map aanmaken en initialiseren
make-cadir ~/openvpn-ca
cd ~/openvpn-ca
./easyrsa init-pki

# Certificaten genereren zonder wachtwoordrestrictie (nopass)
./easyrsa build-ca nopass
./easyrsa gen-req server nopass
./easyrsa sign-req server server

# Diffie-Hellman parameters en TLS-sleutel genereren
./easyrsa gen-dh
openvpn --genkey secret ta.key

Stap 3: Client Certificaat Genereren en Bestanden Kopiëren

bash# Maak een sleutel aan voor de client machine
./easyrsa gen-req client1 nopass
./easyrsa sign-req client client1

# Kopieer de gegenereerde sleutels naar de juiste OpenVPN systeemmappen
sudo cp pki/ca.crt pki/issued/server.crt pki/private/server.key dh.pem ta.key /etc/openvpn/server/

Stap 4: Server Configureren en Route Pushen

Maak het server configuratiebestand aan:

bashsudo nano /etc/openvpn/server/server.conf

Plak de volgende configuratie erin. **Zorg dat de push-route naar jouw interne Windows LAN verwijst!**

textport 1194
proto udp
dev tun
ca ca.crt
cert server.crt
key server.key
dh dh.pem
server 10.8.0.0 255.255.255.0
# HIER DE INTERNE ROUTE PUSHEN RICHTING WINDOWS AD NETWERK:
push "route 192.168.1.0 255.255.255.0"
keepalive 10 120
tls-auth ta.key 0
cipher AES-256-GCM
user nobody
group nobody
persist-key
persist-tun
status openvpn-status.log
verbosity 3

Start de VPN-server-service op:

bashsudo systemctl enable --now openvpn-server@server

Volledig Werkprotocol: Voorbeeldtoets E

Focus: Netwerkinfrastructuur (RRAS / NAT) en Group Policies (GPO).

Toetsduur: 45 Minuten. Geen screenshots inleveren; live controle door beoordelaar op jouw schermen.

Fase 1: Systeemnamen & VMware Netwerken Klaarzetten (0-10 min)

  1. Log in op de Windows GUI router en hernoem de computer naar `RRAS1`. Start direct een herstart.
  2. Log in op de Core server. Typ `sconfig`, kies optie 2 (Computer Name), wijzig naar `Core1` en herstart.
  3. Open de Virtual Machine Settings in VMware en deel de netwerkkaarten exact zo in:
    • DC1: Gekoppeld aan de interne switch waar je Active Directory leeft (bijv. VMnet0).
    • RRAS1 (Router): Moet in totaal 3 netwerkkaarten bezitten:
      - Adapter 1: VMnet0 (Interne koppeling met DC1).
      - Adapter 2: Gekoppeld aan Custom -> VMnet2 (Koppeling met Core1).
      - Adapter 3: Gekoppeld aan Custom -> VMnet8 (NAT) (Koppeling met internet).
    • Core1: Gekoppeld aan Custom -> VMnet2.

Fase 2: IP-Adressering & Ping Activeren (10-20 min)

  1. Op RRAS1: Geef de interface in `VMnet2` het IP 172.19.19.1 (Subnet: `255.255.255.0`, geen gateway). De interface in `VMnet0` krijgt 192.168.1.10.
  2. Op Core1: Typ `sconfig` -> kies optie 8 (Network Settings) -> Selecteer de netwerkkaart.
    • Kies optie 1 (Set Network Adapter Address) -> Typ S (Static).
    • IP-adres: 172.19.19.2 | Subnetmasker: 255.255.255.0
    • Standaard Gateway: Het IP van de router: 172.19.19.1
    • Kies optie 2 (Set DNS Servers) -> Vul het IP van je DC1 in: 192.168.1.1
  3. Ping aanzetten op Core1: In `sconfig` -> Kies optie 4 (Configure Remote Management) -> Kies optie 3 (Configure Server Response to Ping) -> Klik op Yes (Enabled).

Fase 3: RRAS NAT Installeren & Prioriteit Dwingen (20-30 min)

  1. Installeer de Remote Access rol op RRAS1 via PowerShell: 
    powershellInstall-WindowsFeature -Name RemoteAccess, Routing -IncludeManagementTools
  2. Open rrasmgmt.msc. Rechtermuisknop op servernaam -> Configure and Enable Routing... -> Kies NAT -> Selecteer de interface die verbonden is met **VMnet8** (Internet) en rond de wizard af.
  3. Gatway metric forceren op RRAS1 via PowerShell: 
    powershellSet-NetIPInterface -InterfaceAlias "VMnet8" -InterfaceMetric 5
Set-NetIPInterface -InterfaceAlias "Ethernet 0" -InterfaceMetric 80
Set-NetIPInterface -InterfaceAlias "Ethernet 1" -InterfaceMetric 80
Mijlpaal Test: Typ op Core1 `ping 8.8.8.8` en `ping 192.168.1.1`. Krijg je 4x antwoord? Dan is deel 1 (PLF08) 100% gefixed!

Fase 4: Group Policies (GPO) Inrichten (30-45 min)

  1. Gebruiker Bob aanmaken: Open op DC1 *Active Directory Users and Computers* (`dsa.msc`). Maak een OU aan genaamd `ToetsOU`, en maak daarin de gebruiker `bob` aan.
  2. GPO "norun" bouwen: Open *Group Policy Management* (`gpmc.msc`).
    • Maak onder Group Policy Objects een GPO aan genaamd `norun`.
    • Rechtermuisknop -> *Edit*. Ga naar: `User Configuration -> Policies -> Templates -> System`. Zet Prevent access to the command prompt op **Enabled**.
    • Koppel `norun` aan de OU `ToetsOU`. Rechtermuisknop op de koppeling -> Vink **Enforced** aan.
  3. GPO "wachtwoord" bouwen:
    • Maak onder Group Policy Objects een GPO aan genaamd `wachtwoord`.
    • Rechtermuisknop -> *Edit*. Ga naar: `Computer Configuration -> Policies -> Windows Settings -> Security Settings -> Account Policies -> Password Policy`.
    • Stel in: *Enforce password history* = **3**, *Maximum password age* = **20**, *Minimum password length* = **10**.
    • Koppel deze GPO direct aan de ROOT van het domein (bijv. school.test). Rechtermuisknop op deze koppeling -> Vink **Enforced** aan.
  4. Verplicht HTML Rapport genereren op DC1 via PowerShell: 
    powershellGet-GPO -Name "wachtwoord" | Get-GPOReport -ReportType HTML -Path C:\report.html
Eindcontrole voor de docent: Log in op PC1 als `bob`. Probeer CMD te starten (moet blokkeren). Open `C:\report.html` op het scherm van de DC en laat het openstaan voor de beoordelaar.

Volledig Werkprotocol: Voorbeeldtoets F

Focus: Linux OpenVPN Tunneling en Active Directory Sites & Replication.

Fase 1: Linux Netwerkkonstruksie & Repository Reparatie

  1. Laad `rocky2` in via VMware: `VM -> Open -> E:\Childs\rocky2 (RL8)\rocky2.vmx`.
  2. Zet de netwerkkaarten in VMware goed:
    • rocky1 (VPN Server): Interface 1 = `VMnet0` (Interne switch met DC1). Interface 2 (Toevoegen!) = `Custom -> VMnet8 (NAT)`.
    • rocky2 (VPN Client): Enige interface = `Custom -> VMnet8 (NAT)`.
  3. Repareer de repositories op BEIDE Linux machines: 
    bashsudo rm -f /etc/yum.repos.d/Rocky-*
sudo dnf reinstall rocky-repos -y
sudo dnf install epel-release -y
sudo dnf install openvpn easy-rsa -y

Fase 2: Certificaten & VPN Configureren op Rocky1

  1. Initialiseer Easy-RSA op `rocky1`: 
    bashmake-cadir ~/openvpn-ca && cd ~/openvpn-ca && ./easyrsa init-pki
  2. Pas de certificaatgegevens aan: `nano vars`. Pas de velden onderaan aan naar de criteria uit de toets: Country = `NL`, Province/City = `Utrecht`, Org = `Institute for ICT`, Email = `admin@ict.test`.
  3. Genereer de server- en clientsleutels: 
    bash./easyrsa build-ca nopass
./easyrsa gen-req server nopass
./easyrsa sign-req server server
./easyrsa gen-dh
openvpn --genkey secret ta.key
./easyrsa gen-req client1 nopass
./easyrsa sign-req client client1
  4. Verplaats alles naar de openvpn map: 
    bashsudo cp pki/ca.crt pki/issued/server.crt pki/private/server.key dh.pem ta.key /etc/openvpn/server/
  5. Maak de server configuratie aan: `sudo nano /etc/openvpn/server/server.conf`. Plak de standaardconfiguratie erin en zorg dat deze regel erin staat om het interne LAN te pushen:
    push "route 192.168.1.0 255.255.255.0"
  6. Start de server: `sudo systemctl enable --now openvpn-server@server`.

Fase 3: Client Koppelen (rocky2) & Verbinding Verifiëren

  1. Zet de bestanden `ca.crt`, `client1.crt`, `client1.key` en `ta.key` op een veilige manier over naar `rocky2` (bijvoorbeeld via SCP of een gedeelde map).
  2. Maak op `rocky2` het bestand `/etc/openvpn/client/client.conf` aan.
  3. Vul bij de regel remote [IP-ADRES] 1194 het exacte **NAT-IP-adres** van `rocky1` in.
  4. Start de VPN client op `rocky2`: 
    bashsudo systemctl enable --now openvpn-client@client
Mijlpaal Test: Typ op `rocky2` het commando `ping 192.168.1.1`. Krijg je antwoord van de Windows DC? Dan werkt de Linux VPN-tunnel foutloos.

Fase 4: Active Directory Sites & Replicatieschema

  1. Promoveer `Core1` tot extra domeincontroller in het domein `school.test` (Zie stappen bij week 09).
  2. Open Active Directory Sites and Services (`dssite.msc`) op de hoofd-DC.
  3. Maak twee nieuwe sites aan: `Leeuwarden` en `Groningen`.
  4. Sleep server `DC1` naar site Leeuwarden, en server `Core1` naar site Groningen.
  5. Maak de subnets aan: `192.168.1.0/24` (Koppelen aan Leeuwarden) en `172.19.19.0/24` (Koppelen aan Groningen).
  6. Ga naar `Inter-Site Transports -> IP`. Open de eigenschappen van de sitelink.
    • Zet Replicate every op 30 minuten.
    • Klik op Change Schedule. Selecteer Maandag t/m Vrijdag tussen 09:00 en 18:00 -> zet op *Replication Available*. Zet de rest van de uren/vakken volledig op *Not Available* (wit).
  7. Forceer de initiële replicatie via de opdrachtprompt: 
    cmdrepadmin /syncall /AePdq
Laat voor de docent het visuele schema (Change Schedule) openstaan op je scherm en typ `repadmin /showrepl` om aan te tonen dat de synchronisatie vlekkeloos is verlopen.
